# Deploy TOM: Vercel + Render

## 1. Deploy the API on Render

1. In Render, select **New > Blueprint** and connect this GitHub repository.
2. Render detects `render.yaml`. Create the `tom-api` web service.
3. Deploy the service and copy its public URL, such as `https://tom-api.onrender.com`.

The configured persistent disk keeps `chats.db` across restarts and deploys. Do not use an ephemeral filesystem for stored consented chats.

## 2. Deploy the frontend on Vercel

1. In Vercel, import this GitHub repository.
2. Set the **Root Directory** to `Frontend`.
3. Add the environment variable below for the Production environment:
   - `VITE_API_BASE_URL=https://tom-api.onrender.com`
4. Deploy. Copy the Vercel production URL.

## 3. Finish the connection

1. Return to Render and set `CORS_ORIGINS` and `FRONTEND_URL` to the Vercel production URL.
2. Redeploy the Render API.
3. In the live frontend, test `/api/health`, consent, chat, deletion, and the privacy-policy link.

## Production safeguards

- `FLASK_SECRET_KEY` is generated by Render; never commit a real secret.
- The stored-chat dashboard and its `/api/stats` and `/api/chats` endpoints are disabled on Render production deployments.
- Vercel environment variables prefixed with `VITE_` are included in the browser bundle. Only put the public API URL in `VITE_API_BASE_URL`.
